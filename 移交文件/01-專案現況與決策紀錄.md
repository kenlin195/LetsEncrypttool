# 專案現況與重要決策紀錄

## 業主需求摘要

- Windows Server 2016 以上、IIS 10、x64 Desktop Experience。
- 支援一般單網域及同一 IIS 網站的 SAN 多網域。
- 使用 HTTP-01；Internet Port 80 必須可連入。
- 工具要先檢查 DNS、CAA、HTTP 路徑、IIS、Binding、服務、權限、憑證存放區與 win-acme 完整性。
- 正式簽發前必須先通過 Let’s Encrypt Staging。
- 正式憑證安裝到 IIS，並由 SYSTEM 工作排程自動續期。
- GUI 有「登入 Windows 後自動開啟」勾選，但不得收集或保存管理員密碼；權限交給 Windows UAC。
- 「關於我們」顯示名世科技 Logo、版本與公司聯絡資訊。
- 顯示版本格式依業主指定為 `1.1v`，不是一般常見的 `v1.1`。

## 已確立的安全架構

- GUI 以 `asInvoker` 執行；需要管理員能力時啟動同一 EXE 的 elevated worker。
- worker protocol v2：request 以 SHA-256 驗證，result 以每次操作隨機 HMAC-SHA256 驗證。
- worker 只接受 typed payload 與明確 action allow-list，不接受外部傳入任意 executable 或 CLI。
- 三階段 gate：公開預檢 → UAC 本機預檢 → Let’s Encrypt Staging。設定指紋改變或超過 30 分鐘即失效。
- Staging 使用 `--test`、PFX file store、`--installation none`、`--notaskscheduler`；PFX 位於受保護 ProgramData GUID 目錄，完成後必須確認刪除。
- Production 使用固定 Production endpoint、固定 renewal ID、`WebHosting`、IIS＋retention script、`--nocache`、`--keepexisting`、`--notaskscheduler`。
- 正式操作前快照本次 renewal 並建立 IIS appcmd backup。執行失敗或簽發後驗證不符時復原兩者。
- 正式成功不能只相信 wacs exit code，還要核對 renewal JSON、SAN、私鑰、WebHosting、選取網站全部 443 SNI Binding 與共同 thumbprint。
- SYSTEM 續期排程僅在正式憑證與 Binding 驗證成功後建立，且只接受單一 `wacs.exe --renew` 動作。
- 舊憑證清理採 fail-closed：任何 IIS HTTPS Binding 或 HTTP.sys sslcert 仍使用、或查詢失敗，都保留舊憑證。

完整且具約束力的安全不變條件在 `Mstech.IisSslManager/AGENTS.md`。若本文件與 `AGENTS.md` 衝突，以 `AGENTS.md` 與目前程式碼為準，先停下查證，不可直接弱化安全條件。

## 目前已知限制與風險

- 尚未做公司 Code Signing，UAC 會顯示未知的發行者。
- 尚未完成真實 Windows Server＋公開網域的完整驗收矩陣。
- 不支援 Wildcard、DNS-01、Server Core、跨站台 SAN、Central Certificate Store、遠端 IIS、CDN/WAF/LB 自動設定。
- 沒有電子郵件或 Teams 續期失敗通知。
- 目前目錄沒有 Git 歷史；若改壞只能依移交 ZIP／發行 ZIP 與人工備份復原。
- UI 的「固定測試版本」容易被誤認為 beta；可列為下一個純文案修正，但不可刪除 Staging 安全步驟。
